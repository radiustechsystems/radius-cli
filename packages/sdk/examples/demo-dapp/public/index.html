What this shows

radius-sdk makes an HTTP endpoint chargeable, and makes a client (a person, a script, or an agent) able to pay for it, using the open x402 v2 protocol with settlement on Radius in SBC. Nothing Radius-specific travels on the wire, so any x402-capable client can pay a radius-sdk endpoint, and radius-sdk clients can pay any x402 v2 endpoint on Radius.

Seller side: this worker

The endpoints in the paid endpoints card are protected by one Hono middleware. A request without payment gets a 402 with a PAYMENT-REQUIRED header describing the price. A request carrying a signed PAYMENT-SIGNATURE is verified and settled on Radius through the Radius facilitator before the handler runs, and the response carries a PAYMENT-RESPONSE receipt.

import { radiusPayments } from 'radius-sdk/hono';

app.use('/api/*', radiusPayments({
  network: 'testnet',
  payTo: (c) => c.env.PAY_TO,
  routes: {
    'GET /api/quote':  { price: '$0.001', description: 'A quote' },
    'POST /api/echo':  '$0.01',
  },
}));
app.get('/api/quote', (c) => c.json({ …, paidBy: c.get('radiusPayment')?.payer }));

Buyer side: this page

Every "Pay & fetch" button is a fetch wrapped by createRadiusFetch. It sees the 402, checks the offer against your per-request ceiling and network, signs a Permit2 transfer (plus a gasless EIP-2612 permit when the facilitator sponsors approvals, or one on-chain approval when it does not), retries, and hands you the response with a decoded receipt.

import { createRadiusFetch, getPaymentReceipt } from 'radius-sdk/client';

const payFetch = createRadiusFetch({
  network: 'testnet',
  signer: privateKey,          // or a viem account / MetaMask WalletClient
  maxPerRequest: '$0.01',      // hard ceiling, not a budget
  onPaymentRequired: (offer) => confirm(`Pay ${offer.amountFormatted}?`),
});
const res = await payFetch('/api/quote');
const receipt = getPaymentReceipt(res);   // { transaction, payer, amount, explorerUrl }

Try it: 1 Faucet drip into the burner wallet (testnet gives ~0.5 SBC) → 2 "Fetch unpaid" on a route to see the raw 402 → 3 "Pay & fetch" and follow the explorer link in the receipt → 4 try /api/premium to see the ceiling refuse a $5 offer → 5 paste the transaction hash into Reconcile. Toggle the client settings to see declines and approval vetoes.
